# Google 구독 캘린더 · D-Day 3 3.4.0

Google 계정의 기본·구독·공유 캘린더를 선택해 위젯에 표시하고, 날짜를 눌러 일정을 D-Day로 가져옵니다. 공식 배포본은 앱에 포함된 운영 OAuth 정보로 연결하며 사용자가 JSON을 만들 필요가 없습니다. 직접 빌드할 때의 개인 OAuth JSON 연결은 고급 옵션입니다. 실제 운영 OAuth 정보와 사용자 토큰은 공개 소스에 포함하지 않습니다. Google 로그인을 생략하고 웹페이지의 일정을 읽는 방식은 지원하지 않습니다.

## 일반 사용자: 처음 연결하기

1. 설정 → **캘린더 연동 → Google 캘린더 연결·선택…**을 엽니다.
2. **Google 계정 로그인…**을 누릅니다. 공식 배포본은 앱의 OAuth 정보로 연결하므로 사용자가 Cloud 프로젝트나 JSON 파일을 만들지 않습니다.
3. 기본 브라우저에서 **자신의 Google 계정**을 선택하고 캘린더 목록과 일정의 두 읽기 권한을 허용합니다. 앱은 Google의 원본을 작성·수정·삭제하지 않습니다.
4. 앱으로 돌아오면 자신의 기본·구독·공유 캘린더 중 표시할 항목을 선택하고 **선택 저장**을 누릅니다. 최대 20개입니다. 모두 해제하면 연결은 유지하면서 조회·표시를 끕니다.
5. 달력 날짜를 누르고 가져올 일정을 선택해 **D-Day 등록**을 누릅니다. 같은 날짜에 여러 일정이 있으면 선택 목록이 나옵니다.

로그인은 3분 이내에 완료하거나 연결 창을 닫아 취소합니다. Google 비밀번호는 Google 페이지에서만 입력합니다. 학교·기업 Workspace 계정은 조직 관리자 정책에 따라 연결이 제한될 수 있습니다. 구독·공유 캘린더는 Google 웹에서 먼저 해당 계정에 추가하고 읽기 권한을 받아야 합니다.

기존 개인 OAuth 연결은 업데이트 후에도 같은 Windows 계정에서 계속 사용할 수 있습니다. 운영 클라이언트로 전환하려면 기본 로그인 버튼으로 다시 로그인하고 캘린더를 선택합니다.

연결·해제는 즉시 적용되고 캘린더 선택은 ‘선택 저장’으로 확정됩니다. 환경설정의 일반 저장·취소나 기본 설정 초기화와 독립적으로 관리합니다. 연결하지 않아도 로컬 시계·달력·D-Day는 사용할 수 있습니다. 처음에는 연결되지 않은 상태이며 사용자 동작 없이 로그인 창을 띄우지 않습니다.

## 직접 빌드·개인 OAuth 시험

공식 OAuth 정보가 없는 소스 빌드에는 기본 로그인 버튼이 비활성화됩니다. **고급 연결 · 개인 OAuth 클라이언트 → 개인 OAuth JSON으로 연결…**을 사용하세요.

Google Cloud에서 시험 프로젝트를 만들고 Calendar API를 켭니다. Google Auth Platform의 External / Testing에서 본인 계정을 테스트 사용자로 추가하고 다음 두 범위를 등록합니다.

- `https://www.googleapis.com/auth/calendar.calendarlist.readonly`
- `https://www.googleapis.com/auth/calendar.events.readonly`

Clients → Create client → **Desktop app**의 JSON을 다운로드합니다. 웹 앱/서비스 계정 JSON은 사용할 수 없습니다. 파일은 저장소 밖에 보관하고 고급 연결에서 선택한 뒤 위와 같은 브라우저 로그인과 캘린더 선택을 진행합니다. 개인 JSON은 다른 일반 사용자에게 요구하는 절차가 아닙니다.

MathTime 운영 프로젝트의 공개 검증과 정식 빌드 방법은 개발자용 [공식 소스의 OAuth 배포 안내](https://github.com/lottoria-dev/MyDDayWidget-Source/blob/main/GOOGLE_OAUTH_RELEASE.md)에 있습니다. 이 소스 패키지에는 실제 공식 OAuth JSON을 넣지 않았습니다. Google 검증 상태는 운영 프로젝트에서 별도로 확인해야 합니다.

## 구독 캘린더가 보이지 않을 때

먼저 Google 캘린더 웹에서 그 캘린더를 계정에 추가한 후 앱에서 목록을 새로고침하세요. 계정의 CalendarList에 등록되고 일정 읽기 권한이 있는 캘린더가 대상입니다. 단순 웹 링크, Google Tasks, 일정 상세 없이 가능/바쁨만 공유하는 캘린더는 대상이 아닙니다. 제목이 비공개인 개별 일정은 제목을 추정하지 않으며 D-Day 등록을 비활성화합니다.

외부 구독의 업데이트 시점은 Google 및 제공자의 갱신 주기에 영향을 받습니다. 앱의 새로고침은 Google에 반영된 자료를 읽습니다. 여러 Google 계정 중 현재 연결한 계정 하나의 목록만 사용하며 다른 계정으로 다시 연결하면 캘린더를 다시 선택합니다.

## 날짜에서 D-Day 가져오기

- 선택된 Google 캘린더가 있으면 날짜 **한 번 클릭**으로 일정 창이 열립니다. 연결하지 않았거나 모두 해제하면 기존 날짜 더블 클릭의 직접 입력 동작을 유지합니다. 우클릭 메뉴에서도 연결·일정 가져오기·직접 입력에 접근할 수 있습니다.
- 날짜 아래 점과 마우스 오버 팝업에 Google 일정 제목을 함께 표시합니다. 팝업에는 처음 6개와 나머지 개수를 표시하고 전체 목록은 클릭해서 확인합니다. 연·월의 툴팁에서 조회 상태를 확인할 수 있습니다.
- 일정이 하나면 선택된 상태로, 여러 개면 선택되지 않은 목록으로 안내합니다. 가져올 일정을 체크하고 **D-Day 등록**을 누르세요. 동시에 여러 개를 등록할 수 있습니다.
- 종일 일정은 Google의 날짜를 그대로, 시간이 있는 일정은 **PC 시간대**로 변환한 시작 날짜를 사용합니다. 여러 날에 걸친 일정은 해당 기간의 날짜에서 보이지만 D-Day 기준은 항상 일정 시작일입니다. 종료 날짜는 배타적으로 처리하므로 종일 일정의 마지막 날 다음 날짜에는 나타나지 않습니다.
- 반복 일정은 조회 구간에 해당하는 회차로 펼칩니다. 등록 후에는 독립된 D-Day이므로 Google에서 제목·날짜를 변경하거나 취소해도 자동 수정·삭제하지 않습니다. 가져온 항목은 앱 설정에서 편집할 수 있습니다.
- 동일 캘린더의 동일 회차를 다시 가져오면 ‘이미 등록됨’으로 표시합니다. 이 식별자는 설정 편집·정렬·초기화·INI 내보내기/불러오기에서도 유지됩니다. 해당 D-Day를 삭제하면 다시 가져올 수 있습니다. 서로 다른 캘린더에 복제된 일정은 별개의 일정입니다.
- Google 일정이 없을 때는 **직접 입력**을 선택할 수 있습니다. 읽기 오류는 빈 일정과 구분하여 표시합니다.

## 저장·조회 방식

브라우저 로그인에는 PKCE와 임의 state를 사용합니다. 계정 연결 정보와 캘린더 선택은 `%LOCALAPPDATA%\MyDDayWidget\google-calendar.bin`에 Windows DPAPI로 암호화합니다. 액세스 토큰은 메모리에서만 유지하고 갱신 토큰으로 재발급합니다. 다른 PC나 Windows 계정에서는 다시 연결해야 합니다.

API 응답은 일정 식별자·제목·상태·시작/종료, 캘린더 식별자·표시 이름만 요청합니다. 설명·참석자·첨부파일은 요청하지 않습니다. Google 일정 응답은 메모리에 최대 5분 재사용하며 앱을 종료하면 사라집니다. 보이는 달력의 42일 범위와 열어 본 날짜만 조회하고, 위젯이 보이는 동안 5분마다 갱신합니다. 일정 창의 **새로고침**은 캐시를 건너뜁니다. 시간대 차이를 위해 API 요청 범위에 앞뒤 2일을 더한 후 표시 날짜로 걸러냅니다. 취소된 Google 일정은 제외합니다. 월 이동·계정 변경 시 이전 요청을 취소하거나 응답을 무시합니다.

요청당 최대 20초, 목록/일정 작업당 최대 90초이며 로그인은 최대 3분입니다. 각 응답은 4 MiB로 제한하고 캘린더 목록·일정의 후속 페이지도 읽습니다. 한 캘린더·한 조회 범위가 10,000개 일정을 넘으면 오류를 알립니다. 캐시는 최대 64개 범위 또는 20,000개 일정까지 보관합니다. 네트워크 실패 시 같은 범위의 이전 메모리 자료가 있으면 경고와 함께 표시하며, 없으면 조회 실패를 안내합니다. 앱을 재시작한 뒤 오프라인이면 Google 일정을 조회할 수 없지만 이미 등록한 D-Day는 유지됩니다.

INI에는 사용자가 등록한 일정 제목·날짜와 중복 방지용 SHA-256 식별자만 저장합니다. Google 캘린더 원본 ID·이벤트 원본 ID·인증 정보는 INI/내보내기/로그에 넣지 않습니다. 등록한 D-Day의 제목과 날짜는 일반 INI와 백업에 포함되므로 내보낸 파일은 개인 일정 파일로 취급하세요. Google 일정 작성·수정·삭제 API는 사용하지 않습니다.

**연결 해제**는 이 PC의 암호화된 연결 정보와 메모리 조회 결과를 먼저 지우고 Google 권한 철회를 요청합니다. 이미 등록한 D-Day는 유지합니다. 네트워크 오류 등으로 철회가 완료되지 않으면 연결 창의 **Google 연결 권한 관리**에서 직접 해제하세요. 포터블 EXE 삭제만으로 로컬 설정이나 Google 측 허용 권한이 제거되지는 않습니다. 상세한 보존·삭제 방법은 [PRIVACY.md](PRIVACY.md)와 [공개 개인정보 처리방침](https://mathtime.kr/dday-privacy.html)을 참고하세요.

## 로그인 오류와 배포 전 확인

- `access_denied` 또는 계정 제한: 테스트 사용자 등록, Workspace 관리자 정책, 승인한 권한을 확인합니다.
- API 권한 오류: 해당 OAuth 프로젝트에서 Calendar API를 켰는지와 읽기 권한을 확인합니다.
- 브라우저 로그인 후 앱으로 돌아오지 않음: 데스크톱 앱 유형인지 확인하고 로컬 루프백 통신을 막는 PC 정책을 점검합니다.
- 재연결 요구: Google에서 허용을 철회했거나 토큰이 만료된 경우 기본 로그인 버튼 또는 사용했던 고급 개인 연결로 다시 로그인합니다. Google 공식 문서에 따르면 외부 사용자 앱의 **Testing** 상태에서 이처럼 Calendar 권한을 사용하는 갱신 토큰은 7일 만료 제한을 받습니다.
- 공식 OAuth 정보 미포함: 소스 빌드에서 기본 로그인 버튼이 꺼져 있으면 공식 배포본을 사용하거나 고급 개인 JSON 연결을 선택하세요. 정식 배포자는 GOOGLE_OAUTH_RELEASE.md의 운영 구성·검증 절차를 완료해야 합니다.

사용자는 이전 빌드의 실제 Google 연결이 정상 작동함을 확인했습니다. 이번 제작 환경에서는 새 간편 로그인·권한 철회 경로의 실제 Google 계정 로그인과 Windows 실행을 검증하지 못했습니다. Visual Studio에서 빌드한 후 본인 계정의 기본/구독/공유 캘린더, 하루 여러 일정, 종일·반복·다일 일정, 권한 철회와 재연결을 확인하세요. 로컬 가짜 응답으로 자료 처리·페이지·캐시·계정 전환을 검사하는 `DDay3.GoogleChecks.csproj`는 별도 QA 묶음에 있습니다.
